# Личный Веб-Дневник (Django & Bootstrap)
http://81.177.49.243

Современное адаптивное веб-приложение для ведения личных заметок и дневниковых записей. Приложение полностью изолировано для каждого пользователя: каждый видит, создает, редактирует и удаляет исключительно свои собственные записи.

## Функционал приложения

1. **Аутентификация и безопасность:**
   - Регистрация новых пользователей.
   - Авторизация (вход) и завершение сессии (выход).
   - Ограничение доступа к страницам (анонимные пользователи автоматически перенаправляются на авторизацию).
2. **Управление записями (CRUD):**
   - Создание новой записи (Заголовок, Содержание, опциональная загрузка фотографии).
   - Чтение (Просмотр списка всех своих записей и детальной страницы конкретной заметки).
   - Редактирование существующих записей.
   - Удаление записей.
3. **Поиск:**
   - Полнотекстовый поиск по заголовку и содержимому записей на главной странице.
4. **Адаптивный дизайн:**
   - Интерфейс разработан с использованием Bootstrap 5, отлично отображается на смартфонах, планшетах и десктопах.
5. **Панель администратора:**
   - Полная интеграция с Django Admin для управления пользователями и модерации записей.

---

## Стек технологий

- **Backend:** Python 3.12 / Django 5+
- **Frontend:** HTML5, CSS3, Bootstrap 5 (через CDN)
- **База данных:** PostgreSQL 16
- **Асинхронные задачи:** Celery & Redis
- **Продакшен сервер & Прокси:** Gunicorn & Nginx
- **Контейнеризация:** Docker / Docker Compose (Multi-stage сборка)

## Инструкция по установке и запуску (Через Docker)

### 1. Подготовка окружения
Убедитесь, что на вашем компьютере установлены Docker и плагин Docker Compose (современный бесдефисный синтаксис `docker compose`).

Клонируйте репозиторий с проектом или перейдите в его корневую директорию:
```bash
cd personal_diary
```

### 2. Настройка переменных окружения
В корне проекта находится файл `.env.template`. Скопируйте его и переименуйте в `.env`:
```bash
cp .env.template .env
```
Заполните обязательные переменные в файле `.env` своими значениями. **Внимание!** Переменные окружения тянутся кодом строго из среды: если не задать `SECRET_KEY` или данные БД, Django выдаст ошибку `ImproperlyConfigured`. Пароли по умолчанию использовать в продакшене запрещено.

```env
DEBUG=False
SECRET_KEY=ваша_секретная_строка_генерации
ALLOWED_HOSTS=localhost,127.0.0.1,81.177.49.243

# Настройки PostgreSQL
DB_NAME=diary_db
DB_USER=diary_user
DB_PASSWORD=ваш_уникальный_безопасный_пароль_бд
DB_HOST=db
DB_PORT=5432

# Настройки Redis / Celery
REDIS_URL=redis://redis:6379/0
```

### 3. Сборка и запуск контейнеров
Запустите сборку образов и оркестрацию всего стека (Django, PostgreSQL, Redis, Celery, Nginx) в фоновом режиме:
```bash
docker compose up --build -d
```

### 4. Выполнение миграций и сбор статики
Создайте необходимую структуру таблиц в вашей базе данных PostgreSQL внутри запущенного контейнера и соберите файлы статики для веб-сервера:
```bash
docker compose exec web python manage.py migrate
docker compose exec web python manage.py collectstatic --noinput
```

### 5. Создание суперпользователя (Администратора)
Чтобы получить полный доступ к встроенной панели администратора Django, выполните команду:
```bash
docker compose exec web python manage.py createsuperuser
```

### 6. Запуск автоматических тестов
Для валидации работоспособности всех модулей (моделей, форм и контроллеров) проекта выполните команду запуска тестов:
```bash
docker compose exec web python manage.py test
```

## Использование приложения

После успешного выполнения всех шагов приложение станет доступно по следующим адресам:

- **Главный веб-интерфейс**: http://localhost/ (запросы принимает Nginx на 80-м порту и проксирует их в контейнер к Gunicorn).
- **Панель администратора**: http://localhost/admin/ — управление учетными записями, правами доступа и модерация записей дневника.

### Полезные команды Docker Compose:
- Посмотреть статус контейнеров: `docker compose ps`
- Остановка проекта: `docker compose down`
- Просмотр логов веб-приложения: `docker compose logs web`
- Перезапуск Celery воркера: `docker compose restart celery`
